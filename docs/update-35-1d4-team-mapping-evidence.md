# Update 35.1D4 — Offline provider/ESPN team mapping evidence and review gate

**Scope:** An isolated Node.js 22 library and synthetic tests only. Not imported by `functions/index.js`, not deployed, not connected to Firestore, browser, authentication, network, OddsPapi, or research capture. Existing D3 reviewed manifest stays **EMPTY**. No real provider participant IDs or genuine mapping approvals are asserted.

## Starting state and why there is no live mapping

The owner-authorized 35.1C15 audit observed 248 eligible NBA full-game+OT market definitions, 831 matched market objects, and 1,512 active provider price entries. The audit released only aggregates and kept a short-lived in-memory aggregate report, not raw fixture/participant snapshots. Previous observations cannot be reconstructed. Any future real identity evidence must be captured from a **new, separately owner-authorized** backend OddsPapi observation or independently obtained trusted saved source data. Never fetch provider odds automatically or infer a main betting line from unflagged prices.

## D4 offline contracts

- `captureProviderFixture(fixture, metadata)`: extracts a small, allowlisted source record (fixture ID, kickoff, two provider participant IDs, capture reference/timestamp and SHA-256 fingerprint) from an injected NBA OddsPapi fixture. Requires explicit sport 11 / tournament 132, upcoming scheduled fixture, two distinct IDs and safe fields. Discards incoming raw prices, player names, API keys and other provider fields. The fingerprint is only integrity-detection for the normalized record, **not proof of provider origin**.
- `captureEspnEvent(scoreboard, providerStart, metadata)`: extracts a bounded unique ESPN NBA regular-season scheduled event with event ID, kickoff and unique home/away ESPN team IDs. Zero or multiple scheduled event candidates within five minutes means no evidence. Does not guess which provider participant maps to which ESPN team.
- `makePendingTeamCandidate(provider,espn,now)`: requires matching independently captured source records, valid integrity fingerprints, sources within 30 minutes of each other, observations no older than 48 hours, and a fixture >5 minutes / ≤72 hours in the future. Produces **REVIEW REQUIRED** candidate identity data and an integrity fingerprint; no team assignment, approval or betting line selection.
- `makeOfflineTeamReviewGate({authorize,loadCandidate,loadHistory,appendDecision,now})`: a closed-over **server-adapter contract**, *not* a network endpoint or self-authenticating security boundary. It checks authorizer output before any candidate/history read. The authorizer must independently validate Firebase owner identity and return a server-generated opaque reviewer reference. `submit(auth,{fixtureId,action,expectedRevision,pairs?})` accepts `APPROVE`, `REJECT`, `REVOKE`; for approval the explicit two unique participant/team ID pairs must match the stored candidate's exact ID sets. Browser-supplied extra evidence/approval fields are rejected; no source identities can be supplied in the request.
- Approval/revocation records include reviewer reference, review timestamp, action, revision, pinned candidate fingerprint and exact reviewed pair IDs. Read history is strictly sequenced and append-only by contract; **`appendDecision` must enforce an atomic compare-and-set of expected revision and candidate fingerprint in the future production implementation.** A revoked or rejected snapshot cannot be reapproved under the same candidate without a separately reviewed new capture/migration. Concurrent approvals with the same revision must not both succeed.
- `resolve(fixtureQuery)` reconstructs an approved D3 schema-v1 manifest row from **trusted stored** candidate/history and calls the existing D3 reviewed resolver. No raw history is exposed as an authorizing manifest, expired/future/revoked/colliding/mismatched fixture queries fail closed, and neither a browser-supplied ESPN event ID nor team name can override the approved mapping.

All review output remains candidate-only and requires human independent verification: consistency of two event times and sets of two IDs does **not** itself establish how provider participants correspond to ESPN teams. The explicitly reviewed pairing is not inferred from names. An authorizer callback, captured metadata reference, or SHA-256 digest can be forged by untrusted input if wired carelessly; **only future trusted backend ingestion and authorization code can establish genuine provenance**. The pure library deliberately does not claim this by itself.

## Future production integration — separate approval, deployment and API gate

1. Reuse the existing **manually triggered** `oddsPapiNbaMarketAudit` response when the owner separately authorizes a new metered fetch. Backend extraction may record the minimal fixture participant IDs and receipt metadata at the time of that fetch, without creating a second OddsPapi call. Do not assume the historical instance-local aggregate cache can supply missing raw IDs. Verify live provider field shapes first; if required explicit fields are absent, fail closed rather than guessing.
2. Use existing fixed-origin ESPN backend transport with bounded calls and caching, independently retain the official ESPN event/team IDs, and enable owner review only after a separately reviewed Firebase authentication/authorization adapter. No browser direct write permissions: use protected Admin SDK operations and immutable event journal. Protect snapshots and review records from direct browser reads/writes unless explicitly justified.
3. Make storage replay-safe with an atomic transaction enforcing revision and candidate fingerprint; check revocations on every resolution, or rigorously invalidate any caches immediately. Preserve immutable source evidence and audit lineage. Only then consider using the runtime D3 bridge in the D2 adapter for read-only matching.
4. Require **separate owner approval** before any targeted Cloud Functions deployment, production Firestore write or metered OddsPapi call. Preserve six reservations per UTC day, no automatic polling, untouched `oddsPapiAccountPreflight` from held PR #17. Never deploy all functions. Retain `captureAllowed:false`, `autoLineSelected:false`, `bookmakerVerified:false`.

Review the exact PR diff, GitHub Actions and `main` head.

**Not provided by D4:** genuine source snapshots, authenticated production adapter, Firestore schema/deployment, reviewer UI, live ESPN/OddsPapi calls, automatic player mappings, any Betano offer verification, line selection, research capture, model promotion, or ROI/EV evidence. The provider source metadata and reviewer identity in tests are **synthetic**. No Android/PC app test is applicable to the offline-only stage.
